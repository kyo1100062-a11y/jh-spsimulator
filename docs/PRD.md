|------|------|

| **목표** | 내부 직원이 사업의 총사업비를 입력하고 비율을 조정하여, 재원별(국비, 도비, 시비) 보조금액 및 자부담액을 정확하고 신속하게 산출할 수 있도록 지원. 엑셀 수식과 동일한 계산 로직을 웹 기반으로 구현. |

### 2.2. 계산 구조 (테이블 형태)

아래 구조를 테이블 형태로 구현합니다. 디자인 요소는 최소화하고 구조만 유지합니다.

#### (1) 총사업비
- **타입**: 자동 계산 영역
- **설명**: 다른 항목들의 합산으로 자동 계산됨
- **수정 가능 여부**: 읽기 전용 (자동 계산)

#### (2) 교부결정액
- **타입**: 입력 또는 자동계산 방식 설정 가능
- **기본값**: 자동계산 모드
- **설명**: 사용자가 직접 입력하거나 자동 계산 중 선택 가능

#### (3) 사업비 산출금액 (보조금 매칭)
- **타입**: 자동 계산
- **설명**: 보조금 매칭을 위한 산출 금액

#### (4) 보조금 테이블

다음 컬럼 구조의 테이블을 구현합니다:

| 구분 | 재원비율 | 직접입력(계) | 직접입력(국비) | 직접입력(도비) | 직접입력(시비) |
|------|----------|-------------|---------------|---------------|---------------|
| 계 | - | 계산값 | 계산값 | 계산값 | 계산값 |
| 국비 | 입력값(%) | 계산값 | 입력값 또는 계산값 | - | - |
| 도비 | 입력값(%) | 계산값 | - | 입력값 또는 계산값 | - |
| 시비 | 입력값(%) | 계산값 | - | - | 입력값 또는 계산값 |

**기능 요구사항:**
- 각 칸은 입력값 또는 계산값으로 구성
- 기본값: 재원비율은 %로 자동 입력 가능
- 기존 엑셀 수식과 동일하게 작동해야 함
- 입력 즉시 자동 계산 (onChange 기반)

#### (5) 자부담 테이블

다음 컬럼 구조의 테이블을 구현합니다:

| 계 | 보조금매칭비율 | 직접입력 보조금매칭금액 | 부가가치세환급액 | 기타부담금 |
|----|----------------|------------------------|------------------|------------|
| 계산값 | 입력값(%) | 입력값 또는 계산값 | 입력값 | 입력값 |

**기능 요구사항:**
- 입력 / 계산이 가능하도록 구현
- 엑셀의 기존 수식과 동일하게 동작
- 입력 즉시 자동 계산 (onChange 기반)

### 2.3. 핵심 계산 로직 (Core Calculation Logic)

**계산 방식:**
- **자동 계산**: 입력값 변경 시 즉시 자동 계산 (onChange 이벤트 기반)
- **계산하기 버튼 없음**: 모든 계산은 실시간으로 수행됨
- **엑셀 수식과 동일**: 기존 엑셀에서 사용하던 계산 로직을 그대로 구현

**계산 순서:**
1. 총사업비 = 보조금 합계 + 자부담 합계 (자동 계산)
2. 교부결정액 = 입력값 또는 자동 계산값
3. 사업비 산출금액 = 교부결정액 - (부가가치세환급액 + 기타부담금)
4. 보조금 테이블 계산:
   - 재원비율 입력 시 해당 금액 자동 계산
   - 직접입력 시 비율 자동 계산
5. 자부담 테이블 계산:
   - 보조금매칭비율 입력 시 보조금매칭금액 자동 계산
   - 직접입력 시 비율 자동 계산

**참고:**
- 구체적인 계산 수식은 엑셀 파일을 참고하여 구현
- 계산 로직은 함수형으로 깔끔하게 구성하여 추후 수식 변경 시 쉽게 업데이트 가능하도록 구현

### 2.4. 유효성 검증 및 알림 (Validation & Alert)

**검증하기 버튼:**
- 화면에 "검증하기" 버튼 1개만 배치
- 클릭 시 다음 항목을 확인하여 오류를 alert 형태로 표시

| ID | 검증 항목 | 규칙 | 실패 시 액션 |
|----|-----------|------|--------------|
| V01 | 보조금+자부담 합계 검증 | 보조금 합계 + 자부담 합계 = 총사업비 | alert: "보조금과 자부담의 합이 총사업비와 일치하지 않습니다." |
| V02 | 비율 100% 초과 검증 | 모든 비율(%)이 100%를 초과하지 않아야 함 | alert: "비율이 100%를 초과하는 값이 있습니다." |
| V03 | 필수 입력값 검증 | 필수 입력값이 누락되지 않았는지 확인 | alert: "필수 입력값이 누락되었습니다." |
| V04 | 음수 값 검증 | 모든 금액 및 비율이 음수가 아닌지 확인 | alert: "음수 값이 존재합니다." |

**검증 결과 표시:**
- 모든 검증 항목을 순차적으로 확인
- 오류가 발견되면 즉시 alert로 표시하고 검증 중단
- 모든 검증을 통과하면 "검증 완료: 모든 항목이 정상입니다." alert 표시

## 3. 비기능 요구사항 (Non-Functional Requirements)

### 3.1. 성능 및 접근성

- **P01 (속도)**: 모든 계산 로직은 클라이언트 측(Front-End)에서 즉시 완료되어야 합니다 (1초 이내).
- **P02 (사용성)**: 입력값 변경 시 즉시 자동 계산되어 사용자가 결과를 바로 확인할 수 있어야 합니다.
- **P03 (반응성)**: 계산 영역은 시각적으로 구분되어 명확하게 표시되어야 합니다.

### 3.2. 디자인 및 UI/UX

- **D01 (Look & Feel)**: 다크하고 단정한 계산기·데이터 분석 프로그램 느낌의 UI
  - 다크 테마 색상 (어두운 배경, 밝은 텍스트)
  - 군더더기 없이 간결한 입력 필드
  - 계산 영역은 시각적으로 구분 (배경색, 테두리 등)
- **D02 (레이아웃)**: 테이블 형태로 배치
  - HTML table 또는 CSS grid 사용 가능
  - 깔끔하고 심플한 디자인
- **D03 (데이터 표시)**: 금액 표시는 콤마(,)를 사용하여 천 단위 구분 기호를 명확하게 표시해야 합니다 (예: 10,000,000).
- **D04 (입력 필드)**: 입력 필드는 군더더기 없이 간결하게 디자인

## 4. 기술 스택 및 구현 가이드 (Technical Stack & Implementation Guide)

### 4.1. 기술 스택 제약사항

이 애플리케이션은 단순 자료 입력, 계산 기능만 필요하며, 다음 사항들은 **필요하지 않습니다**:
- 서버 (Server)
- 백엔드 (Backend)
- 로그인 기능 (Authentication)
- 데이터 장기 저장 기능 (Persistent Storage)
- PDF 출력 기능 (초기 버전에서는 제외)

**사용 기술:**
- React, Vue 등의 프레임워크 사용 **금지**
- 복잡한 빌드 도구 사용 **금지**
- **순수 HTML5, CSS, JavaScript만 사용**

### 4.2. 프로젝트 구조

프로젝트를 시작하기 위한 최소한의 파일 구조:

```
project-root/
├── index.html      # 메인 레이아웃
├── style.css       # 스타일링, 다크 테마 적용
└── script.js       # 계산 및 이벤트 처리 로직
```

### 4.3. index.html 와이어프레임 구조

**필수 요소:**
- 상단 메타데이터 입력 영역 (보조사업자, 소재지, 사업내역, 업체명, 비고)
- 총사업비 표시 영역 (자동 계산, 읽기 전용)
- 교부결정액 입력/자동계산 영역
- 사업비 산출금액 표시 영역 (자동 계산)
- 보조금 테이블 (HTML table 또는 CSS grid)
- 자부담 테이블 (HTML table 또는 CSS grid)
- 검증하기 버튼
- CSS 연결 코드 (`<link rel="stylesheet" href="style.css">`)
- JavaScript 연결 코드 (`<script src="script.js"></script>`)

**레이아웃 구조:**
- 상단: 메타데이터 입력 영역 (3줄 구조)
- 중앙: 계산 구조 영역
  - 총사업비
  - 교부결정액
  - 사업비 산출금액
  - 보조금 테이블
  - 자부담 테이블
- 하단: 검증하기 버튼

### 4.4. style.css 핵심 스타일 제안

다크하고 단정한 계산기 느낌을 살릴 수 있도록 다음 요소에 대한 CSS 스타일이 필요합니다:

**필수 스타일 요소:**
- 다크 테마 색상 변수 정의 (배경색, 텍스트 색상, 테두리 색상)
- 기본 폰트 설정 (산세리프, 모노스페이스 계열 권장)
- 테이블 스타일 (깔끔한 테두리, 셀 간격)
- 입력 필드 스타일 (간결하고 미니멀)
- 계산 영역 시각적 구분 (배경색, 테두리)
- 검증하기 버튼 스타일
- 자동 계산 영역 읽기 전용 스타일 (배경색으로 구분)

### 4.5. script.js 핵심 로직 구조

**필수 함수:**

1. **계산 함수들 (함수형으로 구성)**
   - `calculateTotalCost()`: 총사업비 계산
   - `calculateSubsidyTable()`: 보조금 테이블 계산
   - `calculateSelfContributionTable()`: 자부담 테이블 계산
   - `calculateProjectCost()`: 사업비 산출금액 계산
   - 각 함수는 독립적으로 구성하여 엑셀 수식 변경 시 쉽게 업데이트 가능

2. **유틸리티 함수**
   - `formatNumber(amount)`: 천 단위 콤마 포맷팅
   - `parseNumber(value)`: 문자열을 숫자로 변환 (콤마 제거)
   - `validateAll()`: 검증하기 버튼 클릭 시 모든 검증 수행

3. **이벤트 핸들링**
   - 모든 입력 필드에 onChange 이벤트 리스너 추가
   - 입력값 변경 시 즉시 관련 계산 함수 호출
   - 검증하기 버튼 클릭 이벤트

**계산 로직 구조:**
- 계산 로직은 함수형으로 깔끔하게 구성
- 엑셀 수식을 제공받으면 해당 함수만 수정하여 업데이트 가능하도록 구조화
- 각 계산 함수는 독립적으로 테스트 가능하도록 구성
